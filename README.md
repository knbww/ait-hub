  # AIT Hub

  Портал участников AIT Club: новости, программа направлений, сдача работ, календарь, AIT Points,
  рейтинг направлений, команды и проекты, каталог конкурсов и чаты.

  <sub>React 19 · TypeScript · Vite · Tailwind CSS 4 · Supabase (Postgres + RLS) · Cloudflare Pages</sub>
</div>

---

## Что внутри

- **Вступление по коду.** У каждого направления свой код вступления; руководитель показывает его
  QR на встрече. Участник сканирует код, заполняет одну форму (имя, класс 7–12, почта, пароль,
  Telegram по желанию, согласие на съёмку) и сразу попадает в своё направление. Без кода аккаунт
  не создаётся.
- **Программа.** 36 недель на каждое из трёх направлений (ИИ, Алгоритмы и олимпиады,
  Стартап-инженерия), заполненные по календарям курсов из Drive: у каждой недели тема, папка
  «Неделя N» в Drive, задание (занятие, практикум, страницы CS50 AI / USACO Guide / Full Stack
  Open, что сдать) и срок. Год начался 5 октября 2026; директор сдвигает недели при каникулах.
- **Работы.** Участник сдаёт ссылку на работу, до трёх файлов по 5 МБ (PDF, картинки, ZIP,
  документы, код) или и то и другое; руководитель направления принимает работу или отправляет на
  доработку с отзывом. Файлы лежат в закрытом хранилище: их видят участник, его руководитель,
  директор и куратор. Посещение отмечает руководитель; очков за него нет.
- **Календарь.** Только форматы клуба (контест, турнир, питч-разбор, симуляция, воркшоп,
  хакатон, Demo Day, TalkX, клубный вечер). Участники видят только подтверждённые события.
  Соревнования из календарей курсов уже стоят черновиками в своих неделях — руководителю остаётся
  поставить день, время и ответственного и подтвердить.
- **Новости.** Посты управления клуба с фото (до шести, сжимаются в браузере, место съёмки
  стирается; автор подтверждает согласие всех на фото), лайками и комментариями. Директор и
  куратор пишут для всего клуба или направления, руководитель — для своего направления.
- **AIT Points (AIP).** Начисляются вручную управлением клуба: сколько, за что и кто подтвердил.
  Журнал только дополняется — ошибку исправляют корректировкой. Лидерборд показывает итоги.
- **Рейтинг направлений.** Три отдельных рейтинга участников и команд. Рейтинг меняется только
  по итогам рейтингового события, правила которого объявлены до начала; с AIT Points не смешивается.
- **Команды** (до 5 человек, внутри направления) и **база проектов**: проблема, пользователь,
  объём, роли, сроки, проверка и показ, вклад каждого с подтверждением руководителя.
- **Конкурсы и возможности.** Каталог олимпиад, конкурсов, хакатонов, стартап-программ,
  стажировок и курсов со сроками, условиями и источниками (первые записи собраны с официальных
  сайтов — [`scripts/catalog`](scripts/catalog)). Участник отмечает «Хочу участвовать» и получает
  напоминание за 3 дня и накануне дедлайна; руководство ведёт каталог и видит, кто отметился.
- **Чаты.** Чат команды, чат проекта и переписка участника с руководством. Читают только
  участники чата (и руководитель направления); директор и куратор разбирают жалобы на сообщения,
  не читая чаты. Сообщения приходят сразу (Supabase Realtime) и пушем.
- **Управление.** Участники и роли, коды вступления, график недель, выгрузка в CSV (резерв на
  случай недоступности Hub), журнал действий, выгрузка и удаление данных участника по запросу.

## Данные участников

Участники — несовершеннолетние, поэтому:

- Hub хранит имя, класс, направление, почту, Telegram, согласие на съёмку, сданные работы,
  посещаемость, AIT Points и результаты — больше ничего.
- Почту, Telegram, работы, посещаемость и детали журнала AIT Points видят только сам участник,
  руководитель его направления, директор и куратор клуба. Остальным участникам видны имя, класс,
  направление, итог AIT Points, рейтинг, команды и проекты.
- Анонимного доступа к данным нет: все правила — в RLS Postgres (`supabase/migrations`), без
  входа доступна только проверка кода вступления. Фото хранятся в закрытом бакете и показываются
  только при согласии на съёмку.
- Данные не уходят во внешние сервисы (никакого ИИ и сторонней автоматизации).
- Любой участник может скачать свои данные в профиле. Полностью удаляет данные по запросу
  директор — на странице участника.

## Разработка

Нужен Node 22 (см. [`.nvmrc`](.nvmrc)).

```bash
npm install
cp .env.example .env.local   # VITE_SUPABASE_URL и VITE_SUPABASE_ANON_KEY
npm run dev                  # http://localhost:5173
```

Проверки (их же запускает CI):

```bash
npm run typecheck
npm run lint
npm run test:db   # все миграции + проверки прав на Postgres в WASM (PGlite), без Docker
npm run build
```

`npm run test:db` прогоняет четыре сценария: апгрейд июньской прод-базы до текущей схемы; чистую
базу с проверкой контента и прав от лица гостя, участника, руководителя, директора и куратора;
демо-данные; аккаунты сотрудников из панели ([`scripts/db-test.mjs`](scripts/db-test.mjs)).

**Демо-копия** — https://demo.ait-hub.pages.dev: отдельный бесплатный проект Supabase
`ait-hub-demo` с вымышленным клубом на 17-й неделе года (участники, команды, проекты, работы,
AIT Points, события с результатами, новости). Данные — [`supabase/seed.sql`](supabase/seed.sql),
пароль всех аккаунтов `demo-ait-2026`, на странице входа — кнопки входа за каждую роль.
`npm run demo` выкатывает новые миграции и сайт, `npm run demo -- --reset` заново раскладывает
данные (даты демо считаются от сегодняшнего дня). Нужны переменные `DEMO_*` в `.env.local`.
`seed.sql` отказывается работать в базе, где уже есть участники, поэтому в рабочую базу не попадёт.

**Первый директор.** Регистрация создаёт только участников. В новой базе зарегистрируйтесь по
любому коду (`select code from join_codes where active`) и выполните в SQL Editor:

```sql
update public.profiles set role = 'director', track_id = null where user_id = '<id из auth.users>';
```

**Директор или куратор с временным паролем.** Без кода аккаунт создаётся только по приглашению с
той же почтой и тем же временным паролем. Приглашение удаляется, как только аккаунт создан; почты и
пароли сотрудников в репозитории не хранятся. Руководители направлений —
школьники: они регистрируются по коду своего направления, роль им даёт директор.

1. SQL Editor (почта — строчными буквами, пароль — от 8 символов; повторный запуск обновляет
   приглашение):
   ```sql
   insert into public.staff_invites (email, role, full_name, temp_password)
   values ('<почта>', 'curator', '<Имя Фамилия>', '<временный пароль>')
   on conflict (email) do update set role = excluded.role, full_name = excluded.full_name,
     temp_password = excluded.temp_password;
   ```
2. Authentication → Add user → Create new user: та же почта, тот же пароль, галочка
   **Auto Confirm User**. Аккаунт сразу получает роль, без направления и класса.
3. Передайте пароль лично. В «Профиле» сотрудник меняет его («Пароль») и включает
   «Двухфакторный вход»: директору и куратору он нужен для выгрузок, удаления и смены ролей.

- «Database error creating new user» — нет подходящего приглашения: шаг 1 пропущен или почта либо
  пароль отличаются от приглашения. Повторите шаг 1 и шаг 2 с теми же почтой и паролем.
- «A user with this email address has already been registered» — с этой почтой уже есть
  аккаунт. Удалите приглашение (`delete from public.staff_invites where email = '<почта>'`);
  роль участнику меняет директор на его странице.

## Выкатка

- **Адрес** — `https://hub.aitclub.org` (домен `aitclub.org`, DNS в Cloudflare). Переменная сборки
  `VITE_PUBLIC_ORIGIN` задаёт адрес для QR-кодов и перенаправляет со старого `ait-hub.pages.dev`.
- **Сайт клуба** — статическая страница из [`site/`](site), отдельный проект Cloudflare Pages
  `ait-club` (`https://ait-club.pages.dev`), выкладка — `npm run deploy:site`. Домены `aitclub.org`
  и `www.aitclub.org` переносятся на него в панели Cloudflare (Pages → проект → Custom domains);
  пока они на `ait-hub`, корень домена перенаправляет в Hub.
- **Фронтенд** — Cloudflare Pages, проект `ait-hub`. После зелёного CI задание `deploy` в
  [`ci.yml`](.github/workflows/ci.yml) собирает и выкладывает `main`. Для него нужны секреты
  репозитория `CLOUDFLARE_API_TOKEN` (права Pages: Edit) и `CLOUDFLARE_ACCOUNT_ID` и переменные
  `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_PUBLIC_ORIGIN` (по желанию `VITE_SENTRY_DSN`).
  Вручную с этого компьютера: впишите `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` в
  `.env.local` (шаблон — [`.env.example`](.env.example)) и выполните `npm run deploy`.
  Заголовки безопасности и запрет индексации — в [`public/_headers`](public/_headers).
- **База** — `npm run db:push` (Supabase CLI, проект привязан через `supabase link`).
- **Настройки входа в Supabase** (Authentication): регистрация по почте включена, подтверждение
  почты выключено (без кода вступления аккаунт всё равно не создаётся), Site URL —
  `https://hub.aitclub.org`, в Redirect URLs — `https://hub.aitclub.org/**`. Вход через GitHub
  работает для тех, кто уже вступил по коду с той же почтой (Supabase связывает аккаунты);
  новый аккаунт через GitHub не создаётся.
- **Бэкапы.** Бесплатный тариф Supabase не делает бэкапов и засыпает после недели простоя.
  Workflow [`backup.yml`](.github/workflows/backup.yml) дважды в неделю снимает дамп базы,
  шифрует его и сохраняет артефактом в GitHub Actions (это же не даёт проекту уснуть). Нужны
  секреты репозитория `SUPABASE_DB_URL` (строка подключения Session pooler) и `BACKUP_PASSPHRASE`.
  Расшифровка: `gpg -d ait-hub-backup.tar.gz.gpg | tar xz`.
